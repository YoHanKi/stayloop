# create-plan

## 0. 호출 시점

다음 조건 중 하나가 충족되면 호출:

- 사용자가 명시적으로 요청 — "{n}주차 plan 만들어줘" / "week{n}-b 짜줘" / "plan Loop 로 정리해줘" / "Skill(create-plan)"
- 새 주차 진입 직전 — *막연한 문제 의식* 만 있는 시점. 본 스킬이 그 막연함을 *Loop 1 의 출발점* 으로 박제.
- 기존 plan 이 *결과 박제* 만 있고 *사고 경로* 가 비어 있는 시점 — 짝 b.md 를 사후 보완.

다음 경우는 호출 X:

- 일회성 작업 / 단일 PR (그건 `create-pr` 영역)
- 결정 1건 박제 (그건 `record-decision` 영역)
- 실험 결과 검토 (그건 `experiment-recurse` 영역)
- 코드 변경 자체 — 본 스킬은 *문서 박제* 만
- 자동 게이트로 호출 X — 명시 호출 전용

## 1. 두 짝 문서의 의미 — 왜 둘인가

**한 plan 으로 묶지 않는 이유**:

| 축 | week{n}-b.md (Loop-driven) | week{n}.md (Closed) |
|---|---|---|
| 시점 | *진입 직후* — 막연함 있는 시점 | *발견 후* — 답이 굳은 시점 |
| 시점 박제 | 발견의 *순서* | 결정의 *결과* |
| 독자 | 새 멤버 / 미래의 자기 자신 — *왜 이 경로를 갔는가* 알고 싶은 사람 | 머지 / PR 분할 / 박제 형식 의 *SSOT* 가 필요한 사람 |
| 갱신 빈도 | Loop 가 *발견* 될 때마다 추가 | Loop 의 결과가 *형식* 으로 굳어질 때마다 갱신 |
| 종결 | 주차 종결 시 read-only | 주차 종결 시 read-only |
| 위험 | *없으면* — closed plan 이 "시니어가 처음부터 알고 시작한 답" 처럼 보임. 학습 손실 | *없으면* — 머지 / 박제 형식 의 SSOT 가 없음. 정렬 손실 |

**week5-b.md 의 §0 "본 문서가 왜 따로 있는가" 참조** — 본 스킬은 그 동기를 형식화한 것.

## 2. Loop 의 형식 — 한 Loop 의 anatomy

각 Loop 는 *사람이 한 번 부딪히고 한 번 고민하고 한 번 결과를 얻는* 단위.

```markdown
## N. Loop K — {한 줄 발견}

**시도.** {실제로 무엇을 했는가 — 명령어 / API 호출 / 측정}

**부딪힘.** {예상과 다른 결과 / 막힌 지점 / 발견된 사실}

**고민 1**: {대안 / 선택지 / 왜 X 가 아닌가}
**고민 2**: {다음 갈림길}
**고민 N**: ...

**결과.** {본 Loop 가 닫히는 시점에 굳은 사실}

➡️ `week{n}.md` 매핑: **PR? / D-? / Phase ? 가 본 Loop 의 산출물**.
```

**필수 요소**:
- *시도* 는 실제 액션 — 추상적 "고민해본다" X. 호출한 명령어 / API / 측정 / 코드 변경 의 *실체*.
- *부딪힘* 은 *예상과 어긋난 사실*. "다 잘 됐다" 는 Loop 가 아님 — 그건 *완료*.
- *고민* 은 *최소 2개 갈림길*. 단일 선택지의 고민은 *고민이 아님* — 그건 *실행*.
- *결과* 는 *닫힌 사실*. "더 봐야 함" 은 Loop 미완 — 다음 Loop 로 분리.
- *매핑* 은 closed plan 의 *구체 위치* 를 가리킨다. 없으면 closed plan 갱신 필요 신호.

**선택 요소**:
- *어디서 막혔는가* 의 출처 (코드 파일 / 외부 자료 / Q&A)
- *시도하기 전 직관* — 후행 학습 자산 (직관 ↔ 실측 차이 박제)

## 3. 문서 전체 구조 — week{n}-b.md 의 골격

```markdown
# {n}주차 진행 흐름 — 사람의 사고 순서 박제 (week{n}.md 의 짝)

> 대상: `docs/presentation/week{n}.md`, `docs/presentation/week{n}-quests.md`
> 짝 문서: `docs/plan/week{n}.md` — **결과를 위한 플랜 (PR / D-N / 박제 형식 사전 박제)**
> 본 문서: **실제 사람이 구현하는 순서 박제** — 구현 → 고민 → 실험 → 결과 → 수정 → 고민 → ...

---

## 0. 본 문서가 왜 따로 있는가
{week5-b §0 의 표현을 본 주차 맥락에 맞춰 변형 — 짝 plan 과의 분담 박제}

## 1. 출발점 — week{n-1} 직후의 막연함
{본 주차 진입 시점에 *알고 있는 것* vs *모르는 것* 박제. 막연한 문제 의식 명시}

## 2 ~ N. Loop 1 ~ Loop M
{§2 의 anatomy 따라 박제. 발견의 순서 그대로}

## N+1. 종합 — 본 흐름이 week{n}.md 의 어떤 부분을 어떻게 생성했는가
{Loop ↔ closed plan 매핑표 — 행: Loop K, 열: 사람의 행동 + week{n}.md 산출물}

## N+2. 본 문서를 어떻게 활용하는가
{시점별 활용 표 — "PR? 진입 전 / 부딪힘 / 회의 / 새 멤버 합류" 별 본 문서 역할}

## N+3. week{n}.md 와의 정합성 약속
{본 문서가 *짝 문서* 라는 약속 — 매핑 / 추가 사실 미박제 / 동시 갱신 / SSOT 분담}
```

**`week5-b.md` 가 정형 예시.** 새 주차 b.md 작성 시 `docs/plan/week5-b.md` 의 구조를 그대로 변형한다.

## 4. closed plan (week{n}.md) 과의 정합 약속

본 스킬이 b.md 를 작성할 때 강제하는 약속:

1. **b.md 의 어떤 Loop 도 closed plan 의 무언가에 매핑된다** — Loop ↔ PR/D-N/Phase 매핑이 없으면 Loop 가 *허공에 떠있음* → closed plan 갱신 필요 신호.
2. **b.md 가 *추가* 사실을 박지 않는다** — closed plan 이 *내용 SSOT*. b.md 는 *경로 박제*. 채택안 / 비교군 / 임계 / 박제 형식 의 *내용* 은 closed plan 이 SSOT.
3. **closed plan 이 갱신되면 b.md 의 매핑 표만 갱신** — Loop 본문은 *발견 시점의 박제* 라 후행 변경 금지.
4. **주차 종결 시 b.md 최종 검수** — §종합 매핑 표 + 본문 Loop 가 모두 closed plan 의 무언가를 가리키는지 확인 후 read-only 로 굳힌다.

이 약속이 깨지면 b.md 는 *틀리거나 죽은 문서*.

## 5. 절차

### Phase 1 — 막연함 박제 (Loop 0 = §1 출발점)

1. **주차 진입 시점 박제**.
   - 이전 주차의 *머지 상태* (어떤 PR 까지 main 에 있는가).
   - 이번 주차의 *quests 한 줄 요약* — `docs/presentation/week{n}-quests.md` 참조.
   - 본인이 *알고 있는 것* — 직전 라운드의 답습 / 기존 코드 / 답습 가능한 패턴.
   - 본인이 *모르는 것* — 무엇이 막연한가. *진짜 첫 질문* 한 줄 박제.

2. **막연함의 *진짜 첫 질문* 박제**.
   - 예: "검색이 느린지 *측정해본 적이 없다*. 어디부터 손대야 할지 모른다."
   - 이 질문이 Loop 1 의 *시도* 를 만든다.

### Phase 2 — Loop 박제 (반복)

각 Loop 마다:

1. **시도 작성** — 실제 행동 (명령어 / 코드 변경 / 측정 / EXPLAIN / k6).
2. **부딪힘 작성** — 예상과 어긋난 사실.
3. **고민 1 ~ N 작성** — *최소 2개 갈림길*. 단일 선택지면 *그게 왜 단일인지* 박제.
4. **결과 작성** — 닫힌 사실.
5. **매핑 작성** — `week{n}.md` 의 PR / D-N / Phase 위치. 매핑 못 하면 closed plan 갱신.

### Phase 3 — 종합 + 활용 + 정합 약속 (마지막 3 절)

1. **§종합 매핑 표** — Loop ↔ 사람의 행동 ↔ closed plan 산출물.
2. **§시점별 활용 표** — "PR 진입 전 / 부딪힘 / 회의 / 새 멤버" 별 본 문서 역할.
3. **§정합성 약속** — §4 의 4 약속 박제.

### Phase 4 — closed plan (`week{n}.md`) 동기화 (선택)

본 스킬이 b.md 작성 후 closed plan 의 매핑 갱신을 권장 (강제 X):

- closed plan 이 *없으면* — b.md 의 결과로 굳은 PR / D-N / Phase 를 closed plan 으로 따로 작성 (별도 작업).
- closed plan 이 *있으면* — b.md 의 매핑이 모두 가리키는 위치가 *존재* 하는지 검증.
- 매핑이 *깨지면* — closed plan 의 해당 절 갱신 필요. 사용자에게 알림.

## 6. 안티 패턴 — *Loop 가 아닌 것*

다음은 b.md 의 Loop 로 박제하지 않는다:

| 안티 패턴 | 왜 Loop 가 아닌가 | 어디로 가야 하는가 |
|---|---|---|
| "X 를 결정했다 — 비즈니스 / 기술 근거" | *결정 박제* 는 `record-decision` 의 D-N | `week{n}/decision.md` |
| "X 코드를 추가 / 수정했다" | *코드 변경 박제* 는 commit 메시지 + PR.md | git log + `documents/feature/{topic}/pr.md` |
| "테스트 추가했다" | *테스트 박제* 는 테스트 파일 자체 + `verify-tests` | 테스트 코드 |
| "다 잘 됐다 / 회귀 없음" | 부딪힘 없는 건 *완료*, Loop 가 아님 | closed plan 의 체크리스트 |
| "다음에 X 를 해야 한다" | *예정* 은 Loop 가 아님 | closed plan 의 다음 PR / week+1 인계 |
| "Y 가 어렵다 / 두려움" | *주관* 만 있는 건 Loop 가 아님 — *실제 행동* 이 있어야 함 | 사용자 1:1 대화 |

## 7. 본 스킬이 *하지 않는 것*

- ❌ closed plan (`week{n}.md`) 을 새로 작성 — 별도 작업 (사용자 / 다른 스킬). b.md 의 매핑이 가리키는 위치를 *검증* 만 한다.
- ❌ 코드 변경 — 본 스킬은 *문서 박제* 만.
- ❌ PR 생성 — `create-pr` 영역.
- ❌ 결정 박제 — `record-decision` 영역.
- ❌ 실험 결과 검토 — `experiment-recurse` 영역.
- ❌ 자동 게이트로 호출 — 명시 호출 전용.

## 8. 호출 예시

### 예시 1 — 새 주차 진입 시점

```
사용자: "6주차 plan 만들어줘. 결제 PG 합류 / Saga / Idempotency 가 본격적으로 들어올 차례."
→ Skill(create-plan)
  - 주차 = 6
  - 출발점: week5 머지 직후 + Saga 한 번도 해본 적 없음
  - 진짜 첫 질문: "PG 호출 직후 우리 서비스가 죽으면 어떻게 되지?"
  - Loop 1: PG 호출 흐름 단순 구현 → 죽음 시뮬레이션 → 환불 / 보상 트랜잭션 필요
  - Loop 2: Saga vs 2PC vs Outbox 갈림길 → ...
  - ...
  - week6.md (closed) 는 별도 작업 / 사용자 결정으로 작성.
```

### 예시 2 — 기존 closed plan 의 짝 b.md 사후 보완

```
사용자: "week5.md 만 있는데 week5-b.md 도 만들자. 사고 흐름이 빠져 있어."
→ Skill(create-plan)
  - 주차 = 5
  - week5.md 의 D-1 ~ D-7 / PR0 ~ PR5 를 *역으로* Loop 로 풀어낸다.
  - 각 Loop 의 매핑이 week5.md 의 어느 위치를 가리키는지 박제.
  - week5.md 갱신 없음 — b.md 만 신설.
```

### 예시 3 — closed plan 갱신이 b.md 갱신을 유발

```
사용자: "week5.md 에 PR6 (어드민 evict 호출) 추가했어. b.md 도 맞춰줘."
→ Skill(create-plan)
  - 주차 = 5
  - week5-b.md 의 §종합 매핑 표에 새 Loop K 추가 (어드민 어디서 발견했는가)
  - Loop K 본문: 시도 (어드민 화면 띄움) → 부딪힘 (캐시 stale) → 고민 (evictPattern KEYS O(N)) → 결과 (어드민 Facade 안 evict 호출) → ➡️ PR6 매핑
  - 본 갱신은 b.md 의 *발견 시점 박제* 정책 (§4-3) 의 *예외*. 사용자가 명시 요청한 경우만 허용.
```

## 9. 산출물 검증 (호출 후 자가 점검)

- [ ] `docs/plan/week{n}-b.md` 가 존재 + §0 ~ §정합성 약속 모든 절 존재
- [ ] §1 출발점 — *진짜 첫 질문* 한 줄 박제
- [ ] 각 Loop — *시도 / 부딪힘 / 고민 ≥ 2 / 결과 / ➡️ 매핑* 5 필드 모두 존재
- [ ] §종합 매핑 표 — 모든 Loop 가 closed plan 의 무언가를 가리킴
- [ ] §시점별 활용 표 — "PR 진입 전 / 부딪힘 / 회의 / 새 멤버" 4 시점 박제
- [ ] §정합성 약속 — §4 의 4 약속 박제
- [ ] closed plan (`week{n}.md`) 의 매핑된 위치가 *모두 존재* (없으면 closed plan 갱신 신호)

## 10. 정형 예시 — `docs/plan/week5-b.md`

본 스킬의 형식 SSOT 는 `docs/plan/week5-b.md`. 새 주차 b.md 작성 시:

1. `docs/plan/week5-b.md` 를 *구조* 만 복사 (Loop 내용은 비움).
2. 새 주차 의 막연함 / Loop 로 채움.
3. closed plan 과의 매핑 갱신.

`week5-b.md` 자체는 본 스킬 호출 *전* 에 작성됨 (스킬의 *출처* 가 본 문서). 본 스킬은 그 형식을 *형식화* 한 결과.
